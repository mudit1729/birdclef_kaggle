# BirdCLEF 2026 Local Pipeline

This repo bootstraps a BirdCLEF 2026 workflow around an EfficientNet-B0 audio model, a Transformer-over-time variant, and Kaggle automation for training and notebook-only submission.

## What is included

- Python 3.11 environment via `uv`
- Kaggle API helpers for:
  - pulling the public baseline notebook
  - downloading competition data on demand
  - submitting Kaggle competition outputs
- Two trainable audio models:
  - `efficientnet_classifier`
  - `efficientnet_transformer_sed`
- A BirdCLEF-style inference script that reads `sample_submission.csv` and emits a valid submission file
- Synthetic smoke tests so the code can be validated without the real competition data

## Architecture Overview

The repo now has two separate Kaggle paths because BirdCLEF 2026 only accepts notebook submissions with `internet = false` and `gpu = false`.

- Training path:
  - local training via `birdclef-train`
  - Kaggle GPU training notebook generated by `scripts/build_kaggle_kernel.py`
- Submission path:
  - checkpoint staged as a Kaggle dataset
  - Kaggle CPU/no-internet submission notebook generated by `scripts/build_kaggle_submission_kernel.py`

## Model Architecture

The repo supports two architectures from `src/birdclef2026/model.py`.

- `efficientnet_classifier`
  - single mel-spectrogram image
  - EfficientNet-B0 classifier head
  - clip-level multilabel logits
- `efficientnet_transformer_sed`
  - mel-spectrogram image
  - EfficientNet-B0 feature extractor
  - token sequence over time
  - Transformer encoder
  - attention pooling
  - clip-level multilabel logits

The Transformer variant is the current main training path used for the remote run and submission notebook.

## Current Training And Evaluation

Training currently does the following:

- load `train.csv` and audio from `train_audio/`
- filter by `min_rating` and optional `max_samples`
- split examples by class into train and validation sets
- optimize `BCEWithLogitsLoss`
- compute validation `macro average precision`
- save the best checkpoint by `valid_map`

The checkpoint that was used for the current submission path came from a one-epoch Kaggle GPU run with:

- `architecture = efficientnet_transformer_sed`
- `image_height = 128`
- `image_width = 256`
- `transformer_dim = 256`
- `transformer_heads = 8`
- `transformer_layers = 2`
- `min_rating = 2`
- `max_samples = 16000`

Recorded remote validation metrics:

- `train_loss = 0.0374`
- `valid_loss = 0.0301`
- `valid_map = 0.0295`

Important limitation:

- There is no strong offline proxy for leaderboard quality yet.
- There is no cross-validation, threshold tuning, calibration, or soundscape-level validation before submission.

## Submission Architecture

Because BirdCLEF 2026 only accepts notebook submissions with `internet = false` and `gpu = false`, the submission flow is split in two:

1. Train remotely in a GPU notebook and save `best_model.pt`.
2. Package that checkpoint as a Kaggle dataset.
3. Run a second CPU-only, no-internet notebook that loads `best_model.pt` and writes `submission.csv`.
4. Submit that notebook version through Kaggle's code-competition API.

That split is implemented by:

- `scripts/build_kaggle_kernel.py`
- `scripts/stage_kaggle_checkpoint_dataset.py`
- `scripts/build_kaggle_submission_kernel.py`

## Improvement Areas

The current system works end to end, but it is still closer to a baseline than a competitive solution. The highest-value improvements are below.

### 1. Make The Model A Real SED Model

- Replace clip-level pooling with framewise logits over time.
- Add a framewise head plus clipwise aggregation instead of only attention pooling.
- Keep token timestamps so post-processing can reason about event duration.
- Add multi-scale time resolution rather than a single resized spectrogram width.

### 2. Improve Validation Quality

- Use stratified fold training instead of a single split.
- Validate at the soundscape level, not only at the clip level.
- Add threshold tuning per class on validation predictions.
- Store out-of-fold predictions for error analysis and ensembling.

### 3. Improve Audio Front-End

- Replace basic `librosa` mel extraction with a torch-native pipeline for faster training and fewer dependency issues.
- Experiment with larger time resolution and less aggressive resizing.
- Tune `n_mels`, `hop_length`, and clip/window strategy around BirdCLEF soundscape scoring.
- Add waveform or spectrogram augmentations such as mixup, time masking, frequency masking, noise, and gain perturbation.

### 4. Improve Training Strategy

- Train for more than one epoch; the current remote run is intentionally short.
- Use learning-rate scheduling and warmup.
- Add class-balanced or focal-style losses for label imbalance.
- Use pseudo-labeling on test soundscapes only if competition rules allow it.
- Run ablations across `efficientnet_classifier` vs `efficientnet_transformer_sed` with consistent folds.

### 5. Improve Inference

- Use overlapping windows instead of only fixed 5-second windows ending at each scoring timestamp.
- Average predictions across multiple crops or test-time augmentations.
- Add per-class calibration and post-processing.
- Ensemble checkpoints, folds, or architectures.

### 6. Improve System Robustness

- Remove the remaining dependence on `librosa` for core training/inference paths.
- Reduce generated-kernel duplication by packaging only what the notebook needs.
- Add tests for the notebook-only submission path.
- Add explicit checks for competition constraints such as `internet=false` and `gpu=false` on the submission notebook.

## Recommended Next Steps

If the goal is leaderboard improvement rather than infrastructure cleanup, the best next sequence is:

1. Add fold-based validation and soundscape-level offline scoring.
2. Train multiple longer runs of `efficientnet_transformer_sed`.
3. Add overlapping-window inference plus threshold tuning.
4. Convert the model from clip-level classification to true framewise SED.

## Requirements

1. Install `uv`: [https://docs.astral.sh/uv/](https://docs.astral.sh/uv/)
2. Put Kaggle credentials in either:
   - `~/.kaggle/kaggle.json`, or
   - `KAGGLE_USERNAME` and `KAGGLE_KEY`
3. Accept the BirdCLEF 2026 competition rules in the Kaggle web UI before running downloads or submissions.

## Setup

```bash
make setup
```

## Pull the baseline notebook

```bash
uv run birdclef-pull-baseline \
  --kernel leonshangguan/faster-eb0-sed-model-inference
```

The notebook and its metadata will be written under `external/kaggle-baseline/`.

## Download competition data

```bash
uv run birdclef-download --competition birdclef-2026
```

This downloads and unzips the competition files into `data/birdclef-2026/`.

## Train

```bash
uv run birdclef-train \
  --download-if-missing \
  --epochs 3 \
  --batch-size 8 \
  --clip-seconds 5
```

Artifacts are written to `artifacts/train/`.

## Infer and build submission

```bash
uv run birdclef-infer \
  --checkpoint artifacts/train/best_model.pt \
  --download-if-missing
```

This creates `artifacts/infer/submission.csv`.

## Submit To Kaggle

```bash
uv run birdclef-submit \
  --file artifacts/infer/submission.csv \
  --message "efficientnet-b0 baseline"
```

This direct CSV upload path is kept in the repo as a generic helper, but BirdCLEF 2026 itself does not accept direct CSV submissions. For this competition, use the notebook-only submission path documented below.

## Run On Kaggle GPU

The repo includes a Kaggle script kernel at `kaggle/birdclef_2026_gpu/` that is generated as a single file because Kaggle script uploads only keep the entry script and metadata.

Build the kernel source:

```bash
make build-kaggle
```

Push it to Kaggle:

```bash
make push-kaggle
```

Check status:

```bash
uv run kaggle kernels status muditjain1729/birdclef-2026-eb0-gpu-baseline
```

Download the remote run outputs or logs:

```bash
uv run kaggle kernels output muditjain1729/birdclef-2026-eb0-gpu-baseline -p /tmp/birdclef_kernel_output
```

The remote kernel currently trains a one-epoch transformer-on-EfficientNet-B0 model on up to 16,000 clips with `rating >= 2`, then writes `/kaggle/working/submission.csv`.

Important: a Kaggle GPU kernel run producing `submission.csv` does not automatically create a competition submission, and BirdCLEF 2026 does not allow direct CSV uploads from the CLI.

Wait for the remote run, download its `submission.csv`, and submit it from your machine:

```bash
uv run birdclef-submit-kernel \
  --kernel muditjain1729/birdclef-2026-eb0-gpu-baseline \
  --message "transformer sed remote run"
```

This polls the training kernel until it completes and downloads the outputs into `artifacts/kernel_output/`. For BirdCLEF 2026, the actual competition submission is done through the separate CPU/no-internet notebook path.

## Run The Submission Notebook

Stage the trained checkpoint as a Kaggle dataset:

```bash
uv run python scripts/stage_kaggle_checkpoint_dataset.py
uv run kaggle datasets create -p kaggle/birdclef_2026_checkpoint_dataset
```

Build and push the CPU/no-internet submission notebook:

```bash
make build-kaggle-submit
make push-kaggle-submit
```

Submit that notebook version to the competition:

```bash
uv run birdclef-submit-code \
  --kernel muditjain1729/birdclef-2026-transformer-sed-submit \
  --kernel-version 2 \
  --message "transformer sed submit kernel"
```

## Smoke tests

```bash
make test
```

The tests generate a tiny synthetic BirdCLEF-style dataset and run a short train/infer cycle without real competition access.
